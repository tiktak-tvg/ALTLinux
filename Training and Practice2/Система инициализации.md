### Система инициализации: SystemV, systemd, управление сервисами и journald
#### 1. Процесс загрузки ОС — продолжение
- После того как загрузчик GRUB2 передал управление ядру Linux, начинается следующий этап — запуск системы инициализации. Ядро запускает самый первый процесс в системе — init (или systemd), который имеет PID 1 и отвечает за запуск всех остальных процессов и служб.
- В процессе загрузки на экране отображаются строки с индикаторами [ OK ] или [FAILED], показывающие статус запуска различных служб. Индикатор [FAILED] свидетельствует о неуспешном завершении этапа загрузки и требует вмешательства администратора. Подробную информацию о шагах загрузки можно получить, нажав клавишу Esc.
- Основные этапы загрузки включают: загрузку ядра, подключение (монтирование) файловых систем и запуск системных служб. Эти этапы могут дополняться проверкой файловых систем на наличие ошибок, что увеличивает время ожидания.
- После завершения загрузки система предоставляет приглашение для входа — в консольном режиме (запрос логина и пароля) или в графическом режиме (менеджер входа gdm).

#### 2. Система инициализации SystemV
**System V init (sysvinit)** — классическая схема инициализации, на которой базируются многие дистрибутивы Linux. Она привычна и довольно проста для понимания: init описывает весь процесс загрузки в своём конфигурационном файле /etc/inittab, откуда вызываются другие программы и скрипты на определённом этапе запуска.

Принцип работы: ``sysvinit`` использует последовательный запуск служб. Каждый уровень выполнения ``(runlevel)`` определяет, какие скрипты должны быть запущены. Скрипты хранятся в каталогах ``/etc/rc.d/`` или ``/etc/init.d/``.

Основные недостатки **SystemV**:
- Последовательный запуск служб приводит к медленной загрузке системы.
- Зависание одного сервиса может остановить весь процесс загрузки.
- Отсутствует развитая система зависимостей между службами.

Тем не менее, команды ``service`` и ``chkconfig`` продолжают работать и в мире ``systemd`` практически без изменений, что обеспечивает обратную совместимость.

#### 3. Система SystemD
**systemd** — альтернативная система инициализации, разработанная как замена для ``sysvinit``. Она вобрала в себя достоинства классического System V init и более современных решений (launchd, SMF, Upstart), но при этом лишена многих их недостатков.

**В ОС «Альт» используется именно systemd (от system daemon)**

Ключевые особенности ``systemd``:

| Особенность    | Описание  |
| :---         | :---          |
Параллельный запуск	      | Высокая степень параллелизации запуска служб благодаря использованию сокетов, что позволяет добиться гораздо более высокой скорости загрузки
Контроль точек монтирования	      | Нежизненно важные файловые системы монтируются только при первом обращении к ним, не тратя время при инициализации
Контроль устройств	      | Можно запускать и останавливать определённые службы при появлении или удалении заданных устройств
Механизм cgroups	      | Используется для отслеживания групп процессов и ограничения потребляемых ими системных ресурсов
Устойчивость	      | Подвисание при запуске одного сервиса не приводит к остановке всего процесса загрузки

**Юниты (units)** — это основные объекты, которыми управляет ``systemd``. Они могут быть разных типов: ``.service (службы), .socket (сокеты), .target (цели загрузки), .mount (точки монтирования)`` и другие.

#### 4. Управление сервисами
Для управления службами в ``systemd`` используется утилита ``systemctl``. Таблица соответствия команд ``SysVinit`` и``systemd``:

| Действие   | Команда SysVinit	   | Команда systemd  |
| :---     | :---          | :---      | 
Запуск службы	     | service frobozz start	     | systemctl start frobozz.service
Остановка службы	     | service frobozz stop	     | systemctl stop frobozz.service
Перезапуск службы	     | service frobozz restart	     | systemctl restart frobozz.service
Перезагрузка конфигурации	     | service frobozz reload	     | systemctl reload frobozz.service
Проверка статуса	     | service frobozz status	     | systemctl status frobozz.service
Включение в автозагрузку	     | chkconfig frobozz on	     | systemctl enable frobozz.service
Отключение из автозагрузки	     | chkconfig frobozz off	     | systemctl disable frobozz.service
Проверка автозагрузки	     | chkconfig frobozz	     | systemctl is-enabled frobozz.service
Список служб	     | chkconfig --list	     | systemctl list-unit-files --type=service
Создание/модификация службы	     | chkconfig frobozz --add	     | systemctl daemon-reload

Примеры команд:

```bash
# Запуск службы
systemctl start NetworkManager.service

# Проверка статуса (показывает, запущена ли служба и включена ли в автозагрузку)
systemctl status NetworkManager.service

# Включение службы в автозагрузку
systemctl enable NetworkManager.service

# Список всех служб
systemctl list-unit-files --type=service

# Установка графического режима загрузки по умолчанию
systemctl set-default graphical.target
```
В ОС «Альт» также доступно управление службами через ``ЦУС и Альт Центр``, где можно включать и отключать systemd-юниты через графический интерфейс.

#### 5. Подсистема журналирования journald
**systemd-journald** — служба, собирающая и хранящая журналы системы в структурированном бинарном формате. Для просмотра журналов используется утилита ``journalctl``.

**Основные команды journalctl**

| Команда      | Описание  |
| :---         | :---          |
journalctl	   | Показать весь журнал (от старых записей до текущих)
journalctl -f	   | Показать последние записи и продолжать вывод в реальном времени
journalctl -r	   | Вывод журнала в обратном порядке (сначала новые)
journalctl -b	   | Показать события текущей загрузки
journalctl -b -1	   | Показать события предыдущей загрузки
journalctl -n 50	   | Показать последние 50 записей
journalctl -u <служба>	   | Показать события указанной службы
journalctl -k	   | Показать сообщения ядра
journalctl -xe	   | Показать последние ошибки с пояснениями
journalctl --disk-usage	   | Показать объём дискового пространства, занимаемого журналами
journalctl --list-boots	   | Просмотреть список загрузок

**Фильтрация записей**
```bash
# Показать сообщения определённой службы за вчера
journalctl -u network.service --since yesterday

# Показать сообщения службы в текущей загрузке
journalctl -b -u network.service

# Показать сообщения процесса с PID=1 (systemd)
journalctl _PID=1

# Показать сообщения от указанного пользователя
journalctl _UID=<uid>

# Фильтрация по времени
journalctl --since "2025-03-01" --until "2025-03-02"
```
**Уровни приоритета**

``journalctl`` поддерживает фильтрацию по уровню приоритета:

| Код	     | Уровень	     | Описание  |
| :---     | :---          | :---      | 
0	  | emerg	  | Система неработоспособна
1	  | alert	  | Требуется немедленное вмешательство
2	  | crit	  | Критическая ошибка
3	  | err	  | Ошибка
4	  | warning	  | Предупреждение
5	  | notice	  | Значимое событие
6	  | info	  | Информационное сообщение
7	  | debug	  | Отладочная информация

**Ротация и хранение журналов**

Настройки хранятся в ``/etc/systemd/journald.conf``:

```ini
SystemMaxUse=1G           # Ограничение размера хранимых журналов
SystemMaxFileSize=200M    # Ограничение размера отдельных файлов
MaxFileSec=20day          # Максимальное время хранения записей в одном файле перед ротацией
MaxRetentionSec=1month    # Ограничение времени хранения файлов
```
Для ручной очистки старых журналов:

```bash
# Удалить журналы, оставив только последние 200 МБ
journalctl --vacuum-size=200M

# Удалить журналы, оставив только за последний месяц
journalctl --vacuum-time=1months
```
После изменения конфигурации необходимо перезапустить службу:

```bash
systemctl restart systemd-journald
```
Журналы также можно просматривать через ЦУС или Альт Центр с фильтрацией по событиям ядра и конкретным службам.

#### 6. Практическая работа: Примеры
##### Пример 1: Просмотр статуса службы и управление ею
```bash
# Проверить, запущена ли служба NetworkManager
systemctl status NetworkManager.service

# Остановить службу
sudo systemctl stop NetworkManager.service

# Запустить службу
sudo systemctl start NetworkManager.service

# Включить автозагрузку
sudo systemctl enable NetworkManager.service

# Проверить, включена ли служба в автозагрузку
systemctl is-enabled NetworkManager.service
```
##### Пример 2: Просмотр журнала загрузки системы
```bash
# Список всех загрузок
journalctl --list-boots

# Показать журнал текущей загрузки
journalctl -b

# Показать только ошибки текущей загрузки
journalctl -b -p err

# Показать последние 20 записей в реальном времени
journalctl -n 20 -f
```
##### Пример 3: Диагностика проблемы с конкретной службой
```bash
# Показать все сообщения службы за последний час
journalctl -u nginx.service --since "1 hour ago"

# Показать сообщения службы с уровнем error и выше
journalctl -u nginx.service -p err

# Показать последние ошибки системы с пояснениями
journalctl -xe
```
##### Пример 4: Управление хранением журналов
```bash
# Посмотреть текущий объём журналов
journalctl --disk-usage

# Очистить архивные журналы, оставив 500 МБ
sudo journalctl --vacuum-size=500M

# Настроить автоматическое ограничение в /etc/systemd/journald.conf
sudo nano /etc/systemd/journald.conf
# Добавить: SystemMaxUse=500M
sudo systemctl restart systemd-journald
```
##### Пример 5: Изменение режима загрузки по умолчанию
```bash
# Переключиться на графический режим загрузки
sudo systemctl set-default graphical.target

# Переключиться на консольный режим загрузки
sudo systemctl set-default multi-user.target

# Проверить текущий режим
systemctl get-default
```
