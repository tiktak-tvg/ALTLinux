### Настройка сети в ОС «Альт»
#### 1. Сетевые подсистемы ОС «Альт»
В ОС «Альт» можно выбрать, какой подсистемой будет обслуживаться конкретный сетевой интерфейс. Выбор осуществляется в модуле ЦУС Ethernet-интерфейсы (раздел «Сеть»).

**Доступные подсистемы**

| Подсистема   | Принцип работы	   | Расположение настроек  |
| :---     | :---          | :---      | 
Etcnet	        | Настройки берутся из файлов в /etc/net/ifaces/<интерфейс>	        | /etc/net/
NetworkManager (etcnet)	        | NetworkManager инициирует сеть, используя параметры Etcnet	        | /etc/net/ + NetworkManager
NetworkManager (native)	        | Управление полностью передано NetworkManager, независимо от Etcnet	        | /etc/NetworkManager/system-connections
systemd-networkd	        | Управление передано службе systemd-networkd	        | /etc/systemd/network/
Не контролируется	        | Интерфейс находится в состоянии DOWN (выключен)        | 	—

> Важно: при смене подсистемы с Etcnet на ``systemd-networkd`` может потребоваться вручную отключить службу ``network`` и включить ``systemd-networkd``.

#### 2. Etcnet
Etcnet — это система управления настройками сети, использующая каталог /etc/net для хранения конфигурационных файлов в декларативном виде. В дистрибутивах ALT она заменяет или дополняет стандартные механизмы (такие как ifupdown) и предоставляет более гибкую модель настройки интерфейсов, VLAN, мостов и туннелей.

Структура каталога /etc/net/
```text
/etc/net/
├── ifaces/              # Каталог с подкаталогами для каждого интерфейса
│   ├── default/         # Базовые настройки (общие для всех)
│   ├── enp0s3/          # Настройки конкретного интерфейса
│   ├── lo/              # Loopback
│   └── unknown/         # Шаблоны для неописанных интерфейсов
├── options.d/           # Общие настройки etcnet (читаются в алфавитном порядке)
├── scripts/             # Пользовательские скрипты при поднятии/остановке
└── sysctl.conf          # Параметры ядра, применяемые после активации
```
**Основные файлы интерфейса**

| Файл         | Назначение	   | 
| :---         | :---          | 
options	       | Основные параметры интерфейса
ipv4address	   | IP-адрес и маска сети
ipv4route	     | Маршрут по умолчанию
resolv.conf    | DNS-серверы и домены поиска

**Параметры файла options**
```text
BOOTPROTO=dhcp          # static / dhcp / ipv4ll
TYPE=eth                # eth / bri / bond / vlan
NM_CONTROLLED=no        # Управление NetworkManager
DISABLED=no             # Отключение интерфейса
CONFIG_WIRELESS=no      # Беспроводной интерфейс
CONFIG_IPV4=yes         # Поддержка IPv4
SYSTEMD_CONTROLLED=no   # Управление systemd-networkd
ONBOOT=yes              # Активация при загрузке
CONFIG_IPV6=no          # Поддержка IPv6
```
**Пример настройки статического IP**
```bash
# Задать IP-адрес и маску
echo "192.168.0.39/24" > /etc/net/ifaces/enp0s3/ipv4address

# Задать шлюз по умолчанию
echo "default via 192.168.0.1" > /etc/net/ifaces/enp0s3/ipv4route

# Задать DNS-сервер
echo "nameserver 192.168.0.1" > /etc/net/ifaces/enp0s3/resolv.conf

# В файле options указать: BOOTPROTO=static

# Применить изменения
systemctl restart etcnet
```
#### 3. NetworkManager
**NetworkManager** — программа для управления сетевыми подключениями, поддерживающая проводные, беспроводные, мобильные, VPN и DSL-соединения.

**Графический интерфейс**

``NetworkManager`` отображается в системном меню верхней панели. Кнопки Проводное и Wi-Fi показывают состояние соответствующего соединения. Нажатие на кнопку меняет состояние.

> Важно: NetworkManager под именем System enp0s3 показывает системное Ethernet-соединение, создаваемое Etcnet. Изменить его в диалоге «Сеть» невозможно — это делается в ЦУС.

**Файлы настроек**

При использовании режима NetworkManager (native) файлы соединений находятся в /etc/NetworkManager/system-connections.

#### 4. nmcli — командный интерфейс
nmcli — консольный инструмент NetworkManager для настройки сети без графического интерфейса.

**Просмотр информации**
```bash
nmcli                          # Общий обзор
nmcli connection show          # Список подключений
nmcli device show              # Информация об устройствах
nmcli device status            # Статус устройств
```
**Настройка статического IP**
```bash
nmcli connection modify enp0s3 \
  connection.autoconnect yes \
  ipv4.method manual \
  ipv4.dns 192.168.1.100 \
  ipv4.dns-search mydomain.dom \
  ipv4.addresses 192.168.1.200/24 \
  ipv4.gateway 192.168.1.1
```
**Настройка динамического IP (DHCP)**
```bash
nmcli connection modify enp0s3 ipv4.method auto ipv4.ignore-auto-dns no
```
Настройка DHCP с явным DNS
```bash
nmcli connection modify enp0s3 \
  ipv4.ignore-auto-dns yes \
  ipv4.dns 192.168.1.100
```  
**Применение изменений**
```bash
nmcli connection down enp0s3 && nmcli connection up enp0s3
Создание VLAN
bash
nmcli connection add type vlan con-name vlan-enp0s3.100 \
  ifname enp0s3.100 dev enp0s3 id 100 ip4 10.10.1.10/24
```
#### 5. systemd-networkd
**systemd-networkd** — системная служба для управления сетевыми настройками, обнаруживающая и настраивающая устройства по мере их появления. Используется, например, в Альт Виртуализация редакция ONE.

**Расположение настроек**

Настройки находятся в каталоге /etc/systemd/network/. Основные типы файлов:

| Расширение   | Назначение	   | 
| :---         | :---          | 
.network	     | Поведение интерфейса (DHCP, статический IP, шлюз, DNS)
.netdev	       | Виртуальные устройства (мосты, VLAN, bond)
.link	         | Свойства аппаратных линков (переименование, MTU)

**Управление службой**
```bash
systemctl start systemd-networkd
systemctl stop systemd-networkd
systemctl restart systemd-networkd
systemctl status systemd-networkd
journalctl -u systemd-networkd
```
#### 6. Разрешение имён узлов
Файл ``/etc/resolv.conf``

**Основной файл для настройки DNS-разрешения.** 

Содержит:
- nameserver — IP-адрес DNS-сервера
- search — домены поиска
- options — дополнительные параметры

**Параметры options**

| Параметр  | Описание	 | 
| :---     | :---          | 
attempts:n	    | Количество попыток запроса к серверам имён
ndots:n	    | Минимальное количество точек в имени
timeout:n	    | Таймаут ожидания ответа
no-check-names	    | Отключение проверки имён

**Домены поиска**

Если в поле Домены поиска указать часто используемые домены, можно пользоваться неполными именами машин (например, computer вместо computer.domain).

#### 7. Утилиты сетевой диагностики

| Утилита   | Назначение	 | 
| :---     | :---          | 
ip addr / ifconfig	    | Просмотр IP-адресов и состояния интерфейсов
ip route / route	    | Просмотр таблицы маршрутизации
ping	    | Проверка сетевой связности (ICMP)
traceroute	    | Трассировка маршрута до узла
arp	    | Просмотр ARP-таблицы
dig	    | Опрос DNS-серверов
nslookup	    | Получение DNS-информации об узле
host	    | Информация о DNS-связях

Примеры команд
```bash
# Проверка связности
ping -c 4 192.168.1.1

# Трассировка маршрута
traceroute 8.8.8.8

# Проверка DNS
dig ya.ru
nslookup ya.ru

# Просмотр маршрутов
ip route
```
#### 8. Практическая работа: Примеры
##### Пример 1. Настройка статического IP через ЦУС
- Открыть ЦУС → Сеть → Ethernet-интерфейсы
- Выбрать интерфейс (например, enp0s3)
- В поле Конфигурация выбрать «Вручную»
- Указать IP-адрес и маску сети
- Указать Шлюз по умолчанию
- Указать DNS-серверы
- Сохранить изменения

##### Пример 2. Настройка через nmcli (статический IP)
```bash
# Установить статический адрес
nmcli connection modify enp0s3 \
  ipv4.addresses 192.168.1.100/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns 8.8.8.8 \
  ipv4.method manual

# Перезапустить соединение
nmcli connection down enp0s3 && nmcli connection up enp0s3

# Проверить
ip addr show enp0s3
ping -c 3 8.8.8.8
```
##### Пример 3. Настройка Etcnet (ручное редактирование)
```bash
# Создать файлы настроек
echo "192.168.0.50/24" > /etc/net/ifaces/enp0s3/ipv4address
echo "default via 192.168.0.1" > /etc/net/ifaces/enp0s3/ipv4route
echo "nameserver 192.168.0.1" > /etc/net/ifaces/enp0s3/resolv.conf

# Отредактировать options: BOOTPROTO=static

# Применить
systemctl restart etcnet
Пример 4. Диагностика проблемы с сетью
bash
# 1. Проверить IP-адрес
ip addr show

# 2. Проверить маршрут
ip route

# 3. Проверить шлюз
ping -c 3 192.168.1.1

# 4. Проверить внешний ресурс
ping -c 3 8.8.8.8

# 5. Проверить DNS
nslookup ya.ru

# 6. Проверить, слушается ли порт
ss -tlnp | grep :22
```
