### Организация хранения данных в ОС «Альт»
#### 1. Разбиение дисков
При установке ОС «Альт» программа установки предлагает два основных профиля разбиения диска: «Установка рабочей станции» (автоматический) и «Вручную» .

**Автоматическое разбиение**
При выборе профиля «Установка рабочей станции» будут выделены отдельные разделы для подкачки (swap), для EFI и для корневой файловой системы . В более новых версиях доступны профили с LVM и Btrfs .

**Ручное разбиение**
Ручной профиль позволяет установить ОС на программный RAID-массив, разместить разделы в томах LVM и использовать шифрование на разделах . Этот вариант требует знаний об устройстве диска и технологиях его разметки .

**Особенности UEFI**
Для корректной работы системы в режиме UEFI при ручном разбиении диска необходимо обязательно создать точку монтирования /boot/efi и смонтировать в неё раздел с файловой системой VFAT (FAT32), содержащий загрузочные файлы . Рекомендуемый размер такого раздела — ~100–500 МБ .

**Остальные разделы — и файловая система, и swap — имеют GPT-тип basic data**

> Предупреждение
Не уменьшайте NTFS-раздел с установленной Microsoft Windows средствами программы установки. В противном случае вы не сможете загрузить Windows после установки Альт .

#### 2. Менеджер логических томов (LVM)
LVM (Logical Volume Manager) — средство гибкого управления дисковым пространством, позволяющее создавать поверх физических разделов (либо неразбитых дисков) логические тома, которые в системе видны как обычные блочные устройства .

**Этапы подготовки к установке на LVM**

Процесс условно делится на шаги :
- Создание разделов на жёстких дисках
- Создание группы томов LVM
- Создание томов LVM
- Создание файловых систем на томах LVM

**Создание разделов для LVM**

При создании разделов для последующего включения их в LVM-тома следует указать Тип раздела равным basic data (в режиме UEFI) или Linux LVM (в режиме Legacy) и не создавать на них том (снять отметку с пункта «Создать том») .

**Важное ограничение**

Системный раздел EFI должен быть физическим разделом в основной таблице разделов диска, не под LVM .

**Создание группы томов**

- После создания разделов в списке выбирается пункт LVM, затем нажимается кнопка «Создать группу томов». В открывшемся окне необходимо выбрать разделы, указать название группы и выбрать размер экстента .
- Размер экстента по умолчанию — 65536 (65536 × 512 байт = 32 МБ, где 512 байт — размер сектора) .
- После создания группы томов её можно использовать как обычный жёсткий диск: внутри группы создаются тома (аналог раздела) и файловые системы .

#### 3. RAID-массивы
RAID (redundant array of independent disks) — технология виртуализации данных, которая объединяет несколько НЖМД в логический элемент для избыточности и повышения производительности .

**Поддерживаемые типы RAID**

Программа установки поддерживает создание программных RAID-массивов следующих типов :

Тип	Описание
RAID 0	Чередование без отказоустойчивости. Ёмкость равна сумме ёмкостей всех дисков. Отказ одного диска ведёт к потере всех данных 
RAID 1	Зеркалирование. Данные записываются одинаково на все диски. Требуется не менее двух дисков одинакового размера. Эффективная ёмкость равна ёмкости одного диска 
RAID 4/5/6	Чередование с распределённой чётностью
RAID 10	Зеркалирование с чередованием. Требуется не менее четырёх дисков 
Этапы создания RAID при установке

Процесс условно делится на шаги :
- Создание разделов на жёстких дисках
- Создание RAID-массивов на разделах
- Создание файловых систем на RAID-массиве
- При создании разделов для RAID следует указать Тип раздела равным Linux RAID .


> Важное замечание
Для создания программного RAID-массива потребуется минимум два жёстких диска . Объём результирующего массива может зависеть от размера включённых разделов: например, при создании RAID 1 результирующий размер будет равен размеру минимального участника .

После создания RAID-массивы можно использовать как обычные разделы — создавать на них файловые системы или включать в LVM-тома .

#### 4. Программный RAID в Linux (mdadm)
**mdadm** — утилита для управления программными RAID-массивами в Linux, работающая через подсистему md (multiple devices) ядра .

**Подготовка дисков**

Перед созданием массива на каждом диске создаётся таблица разделов GPT и один раздел во весь объём с флагом raid :

```bash
sudo parted /dev/vdb --script mklabel gpt
sudo parted /dev/vdb --script mkpart primary 0% 100%
sudo parted /dev/vdb --script set 1 raid on
```
Те же команды повторяются для второго диска (/dev/vdc). В итоге появляются разделы /dev/vdb1 и /dev/vdc1.

Если диски ранее использовались в другом массиве, необходимо очистить остаточные метаданные :

```bash
sudo mdadm --zero-superblock /dev/vdb1 /dev/vdc1
```
Создание массива RAID 1
```bash
sudo mdadm --create --verbose /dev/md0 --level=1 --raid-devices=2 /dev/vdb1 /dev/vdc1
```
Просмотр состояния массива
```bash
cat /proc/mdstat
sudo mdadm --detail /dev/md0
```
**Замена диска в RAID 1**
RAID 1 позволяет удалить или заменить один диск без потери данных :

```bash
# Пометить диск как неисправный
sudo mdadm /dev/md0 --fail /dev/vdb1

# Удалить его из массива
sudo mdadm /dev/md0 --remove /dev/vdb1

# Добавить новый диск
sudo mdadm /dev/md0 --add /dev/vdd1
```
Синхронизацию можно отслеживать через watch cat /proc/mdstat .

> Важное предупреждение
Не смешивайте диски разных размеров. Это ограничит производительность массива скоростью самого медленного диска .

#### 5. Файловые системы
В ОС «Альт» поддерживаются следующие файловые системы :

Файловая система	Характеристика
ext2	Нежурналируемая. Относительно проста в восстановлении, но требует долгой проверки целостности после сбоя. Может использоваться для /boot или readonly-разделов 
ext3	Журналируемая и достаточно надёжная, имеет среднюю производительность 
ext4	Журналируемая, логическое продолжение ext3, позволяет полностью отключить журналирование 
btrfs	Поддерживает снимки, сжатие и подтома 
xfs	Высокопроизводительная журналируемая, имеет более высокую чувствительность к сбоям. Рекомендуется для активно используемых ФС при стабильном питании 
jfs	Журналируемая, имеет поддержку перекодирования имён файлов 
FAT/FAT32/NTFS поддерживаются в установленной системе, но не для установки на них Linux .

#### 6. Файловые системы ext2/ext3/ext4
**Общая характеристика**
Все файловые системы ext, кроме ext2, используют журналирование — методику обеспечения отказоустойчивости, при которой ведётся журнал изменений перед непосредственной записью данных на устройство. Это позволяет избежать повреждения метаданных при сбоях .

**Ключевые различия**

Характеристика	ext2	ext3	ext4
Журналирование	нет	да	да
Совместимость	Базовая	Логическое продолжение ext2, лёгкое взаимопревращение 	Дальнейшее развитие ext3
Производительность	Лучшая среди Linux-ФС по скорости и нагрузке на CPU 	Средняя 	Значительное повышение производительности и надёжности 
Максимальный размер файла (4 КБ блок)	2 ТБ	2 ТБ	16 ТБ
Максимальный размер ФС (4 КБ блок)	16 ТБ	16 ТБ	1 ЭБ
Режимы журналирования
Специфичный для ext3 и ext4 режим data-mode journaling (не используется по умолчанию) журналирует и данные, и метаданные, но со значительным падением производительности. Режим ordered-mode journaling (по умолчанию) журналирует только метаданные .

#### 7. Практическая работа: Примеры
##### Пример 1. Создание LVM при установке
Цель: создать группу томов alt с логическими томами root и swap.

**Шаги**:
- Выбрать профиль «Вручную» на этапе подготовки диска.
- Создать раздел для LVM: тип basic data (UEFI), снять отметку «Создать том» .
- В списке выбрать LVM → «Создать группу томов».
- Выбрать созданный раздел, указать имя группы (alt), размер экстента по умолчанию (32 МБ) .

Внутри группы создать тома:

- root — ext4, точка монтирования /
- swap — SWAPFS, без точки монтирования
- Подтвердить разметку кнопкой «Далее».

##### Пример 2. Создание RAID 1 при установке
Цель: создать зеркальный массив из двух дисков.

**Шаги**:
- Выбрать профиль «Вручную».

На каждом диске создать разделы одинакового размера с типом Linux RAID :
- sda1 (swap, 2048 МБ)
- sda2 (корень, остаток)
- аналогично sdb1, sdb2
- Выбрать в списке RAID → «Создать RAID».
- Выбрать «MD-устройство уровня RAID1» .
- Отметить разделы sda1 и sdb1 → OK. Получится md0.
- Повторить для sda2 и sdb2 → md1.
- На md0 создать файловую систему подкачки, на md1 — ext4 с точкой монтирования /.

> Важно: объём RAID 1 будет равен размеру минимального участника .

##### Пример 3. Создание RAID 1 через mdadm (командная строка)
```bash
# 1. Разметка дисков
sudo parted /dev/vdb --script mklabel gpt
sudo parted /dev/vdb --script mkpart primary 0% 100%
sudo parted /dev/vdb --script set 1 raid on

sudo parted /dev/vdc --script mklabel gpt
sudo parted /dev/vdc --script mkpart primary 0% 100%
sudo parted /dev/vdc --script set 1 raid on

# 2. Очистка старых суперблоков (при необходимости)
sudo mdadm --zero-superblock /dev/vdb1 /dev/vdc1

# 3. Создание массива
sudo mdadm --create --verbose /dev/md0 --level=1 --raid-devices=2 /dev/vdb1 /dev/vdc1

# 4. Проверка
cat /proc/mdstat
sudo mdadm --detail /dev/md0

# 5. Создание файловой системы
sudo mkfs.ext4 /dev/md0

# 6. Монтирование
sudo mkdir /mnt/raid1
sudo mount /dev/md0 /mnt/raid1
```
##### Пример 4. Выбор файловой системы
Сценарий	Рекомендуемая ФС	Обоснование
Раздел /boot	ext2 или ext4	Небольшой размер, важна простота восстановления
Корневая ФС сервера	ext4 или xfs	Баланс надёжности и производительности
Активно используемые данные	xfs	Высокая производительность при стабильном питании 
Система с Timeshift	btrfs	Поддержка снимков для резервного копирования 

> Важно: FAT/FAT32/NTFS нельзя использовать для установки Linux
