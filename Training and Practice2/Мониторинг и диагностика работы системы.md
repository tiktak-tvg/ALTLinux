### Мониторинг и диагностика работы системы в ОС «Альт»
#### 1. Мониторинг загрузки процессора
Для контроля загрузки CPU в ОС «Альт» доступны как графические инструменты, так и консольные утилиты.

**Графический интерфейс**

- Системный монитор отображает информацию о ресурсах в реальном времени в виде графиков, включая использование процессора (CPU), оперативной памяти (RAM) и файла подкачки (SWAP). Во вкладке «Ресурсы» можно наблюдать среднюю загрузку за последние 1, 5 и 15 минут. Каждый запущенный процесс отображается с указанием процента потребления CPU, приоритета и занимаемой памяти.
- При щелчке правой кнопкой мыши по процессу открывается контекстное меню, позволяющее завершить «зависшее» приложение, остановить, перезапустить или изменить его приоритет. Для установки более высокого приоритета потребуется пароль пользователя из группы wheel.
- В «Альт Рабочей станции К» системный монитор Plasma вызывается комбинацией Meta (Win) + Esc.

**Консольные утилиты**

``iostat`` из пакета ``sysstat`` показывает информацию о загруженности процессора и устройствах ввода-вывода:

```bash
$ iostat -c 2 5
```
Ключевые поля вывода:
- %user — использование процессора в пространстве пользователя
- %system — использование процессора ядром
- %iowait — время ожидания операций ввода/вывода
- %idle — время простоя процессора

Большое значение %iowait указывает на то, что процессор простаивает в ожидании завершения операций ввода-вывода.

``mpstat`` — утилита для мониторинга каждого ядра CPU отдельно:

```bash
$ mpstat -P ALL 2 5
```
#### 2. Мониторинг использования памяти
**Графический интерфейс**

Системный монитор отображает объём используемой оперативной памяти и файла подкачки в реальном времени на вкладке «Ресурсы». Список процессов показывает потребление памяти каждым приложением (в мегабайтах или килобайтах).

Консольные утилиты

``free`` — базовая информация о памяти:

```bash
$ free -h
```
Вывод включает общий объём, использованную, свободную память, а также раздел swap.

``vmstat`` — расширенная статистика:

```bash
$ vmstat 2 5
```
Ключевые поля:
- swpd — используемый swap
- free — свободная память
- buff/cache — буферы и кэш
- sar -r — историческая статистика использования памяти:

```bash
$ sar -r 2 5
```
Данные сохраняются в /var/log/sa/saDD, что позволяет анализировать загрузку памяти за прошедшие дни.

**Настройка порогов D-Bus**

В ОС «Альт» реализован сервис D-Bus, возвращающий текущее состояние системы: уровень загрузки CPU, использование оперативной памяти и общее количество активных процессов. Сервис также указывает режим нагрузки — нормальный («Normal Load») или высокий («High Load»).

Пороговые значения настраиваются через методы D-Bus:

```bash
# Установка порога использования памяти в 85%
gdbus call --system --dest <service> --object-path <path> \
  --method <interface>.set_memory_threshold 85
```
Если использование памяти превысит этот предел, система будет считаться перегруженной.

#### 3. Мониторинг ввода-вывода
**Консольные утилиты**
``iostat`` — основной инструмент для анализа дискового ввода-вывода:

```bash
$ iostat -mxd /dev/sda 2 5
```
Ключевые поля расширенной статистики:
- r/s (w/s) — количество запросов чтения (записи) в секунду
- rkB/s (wkB/s) — объём данных, прочитанных (записанных) за секунду
- r_await (w_await) — среднее время завершения запроса в миллисекундах
- aqu-sz — средняя длина очереди запросов
- %util — процент времени, в течение которого устройство было занято обработкой запросов
- iotop — мониторинг ввода-вывода в разрезе процессов:

```bash
# apt-get install iotop
# iotop -o
```
Ключ -o показывает только процессы, активно выполняющие операции ввода-вывода.

``pidstat -d`` — статистика ввода-вывода по конкретным процессам:

```bash
$ pidstat -d 2 5
```
Поля kB_rd/s и kB_wr/s показывают скорость чтения и записи для каждого процесса.

**Тестирование производительности**

``hdparm`` — оценка скорости линейного чтения:

```bash
# sync && echo 3 > /proc/sys/vm/drop_caches
# hdparm -t --direct /dev/sda

/dev/sda:
 Timing O_DIRECT disk reads: 826 MB in 3.01 seconds = 274.71 MB/sec
```
Полученная скорость должна быть близка к заявленной в спецификации на устройство.

#### 4. Мониторинг сетевой активности
Графический интерфейс

Системный монитор отображает использование сети в реальном времени на вкладке «Ресурсы».

**Специализированные приложения**

``Sniffnet`` — приложение для комфортного мониторинга сетевого трафика:

```bash
# apt-get install sniffnet
```
Netvisix — визуализирует поток сетевых пакетов между хостами и предоставляет статистику по каждому хосту. Поддерживает протоколы ARP, IPv4, IPv6, ICMP, TCP, UDP, DNS, DHCP:

```bash
# apt-get install netvisix
```
Консольные утилиты
sar -n — статистика сетевых интерфейсов:

```bash
# Мониторинг всех сетевых метрик
$ sar -n ALL 2 5

# Сохранение в файл
$ sar -n ALL 2 5 -o net.report

# Чтение из файла с фильтром по интерфейсу
$ sar -n ALL --iface=eth0 -f net.report
```
Мониторинг виртуальных машин
В «Альт Виртуализации» OpenNebula собирает метрики использования ресурсов ВМ с помощью агентов мониторинга, работающих на узлах. Данные обновляются каждые 5–10 секунд и доступны через команду onevm show, а также в веб-интерфейсе Sunstone.

Ключевые метрики:

Ключ                | Описание                | Единицы
------------------- | ------------------------- | -------------------------
CPU	 | Загрузка CPU	%  | (1 ядро = 1.0)
MEMORY	 | Используемая память	 | ``КБ``
NETRX	 | Полученные сетевые байты	 | ``—``
NETTX	 | Отправленные сетевые байты	 | ``—``

#### 5. Практическая работа: Примеры
##### Пример 1. Мониторинг загрузки CPU и памяти
Цель: оценить текущую нагрузку на процессор и память.

```bash
# Загрузка CPU (5 измерений с интервалом 2 секунды)
$ iostat -c 2 5

# Использование памяти
$ free -h

# Расширенная статистика виртуальной памяти
$ vmstat 2 5

# Историческая статистика CPU
$ sar -u 2 5

# Историческая статистика памяти
$ sar -r 2 5
```
Анализ: если %iowait в выводе iostat превышает 20–30%, это указывает на проблемы с дисковой подсистемой. Если free показывает малый объём свободной памяти и активное использование swap — система испытывает нехватку ОЗУ.

##### Пример 2. Диагностика дискового ввода-вывода
Цель: определить, какой процесс создаёт нагрузку на диск.

```bash
# 1. Общая статистика по диску
$ iostat -mxd /dev/sda 2 5

# 2. Мониторинг процессов, активно работающих с диском
# apt-get install iotop
# iotop -o

# 3. Детальная статистика по процессам
$ pidstat -d 2 5
```
Интерпретация: высокое значение %util (близкое к 100%) в iostat указывает на饱和ность диска. Высокое r_await или w_await (> 50 мс) свидетельствует о проблемах с производительностью накопителя.

##### Пример 3. Тестирование скорости чтения диска
Цель: проверить соответствие скорости диска заявленной в спецификации.

```bash
$ su -
# sync && echo 3 > /proc/sys/vm/drop_caches
# hdparm -t --direct /dev/sda
```
Результат: скорость линейного чтения должна быть близка к паспортной для данного устройства.

##### Пример 4. Мониторинг сетевой активности
Цель: отследить сетевой трафик и определить загруженность интерфейса.

```bash
# Общая сетевая статистика
$ sar -n DEV 2 5

# Все сетевые метрики
$ sar -n ALL 2 5

# Визуализация трафика между хостами (при установленном netvisix)
# apt-get install netvisix
$ netvisix
```
##### Пример 5. Использование системного монитора для управления процессами
Цель: завершить «зависшее» приложение или изменить его приоритет.

- Открыть Системный монитор (в MATE: Меню → Система → Системный монитор; в KDE: Meta+Esc).

- Перейти на вкладку «Процессы».

- Найти нужный процесс в списке.

Щёлкнуть правой кнопкой мыши и выбрать:

- «Завершить» — принудительно закрыть приложение

- «Изменить приоритет процесса...» — открыть диалог изменения приоритета

- Переместить ползунок для установки уровня nice (меньшее значение = выше приоритет).

- Нажать «ОК».

> Примечание: для повышения приоритета выше текущего потребуется пароль пользователя из группы wheel.

##### Пример 6. Использование порогов D-Bus для автоматического мониторинга
Цель: настроить автоматическое оповещение при превышении нагрузки.

```bash
# Изменение порога загрузки CPU на 90%
# (пример вызова через gdbus)
$ gdbus call --system --dest <service> --object-path <path> \
  --method <interface>.set_cpu_threshold 90

# Изменение порога использования памяти на 85%
$ gdbus call --system --dest <service> --object-path <path> \
  --method <interface>.set_memory_threshold 85

# Мониторинг сообщений D-Bus
$ dbus-monitor --system
После установки порогов система будет возвращать сообщение «High Load» при превышении заданных значений.
```
