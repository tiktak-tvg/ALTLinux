### Организация хранения данных в Linux (ОС «Альт»)
В основе организации хранения данных в Linux лежат два взаимосвязанных понятия: стандарт иерархии файловой системы (FHS) и управление дисковыми разделами. В ОС «Альт» эти механизмы реализованы в полном соответствии с общими принципами UNIX-подобных систем.

#### 1. FHS – Filesystem Hierarchy Standard
FHS (Filesystem Hierarchy Standard) — это стандарт, регламентирующий структуру каталогов в UNIX-подобных операционных системах . Благодаря ему пользователь в любой Linux-системе найдёт знакомые каталоги /etc, /home, /usr/bin и другие.

Ключевые особенности FHS:
- **Единый корень**: В Linux существует только один корневой каталог /, в который «вложены» все остальные каталоги . Это создаёт иллюзию единой файловой системы, даже если физически данные расположены на разных дисках или удалённых машинах.
- **Монтирование**: Разные части файловой системы (разделы дисков, съёмные носители, сетевые ресурсы) подключаются к дереву каталогов через процедуру монтирования . Точкой монтирования служит пустой каталог, в который «прививается» содержимое устройства.

Основные каталоги FHS:

| Каталог | Назначение |
| :--- | :--- |
``/``     | Корень файловой системы
``/bin``	 | Основные исполняемые файлы
``/boot``	 | Файлы загрузчика и ядра
``/dev``	 | Файлы устройств
``/etc``	 | Конфигурационные файлы
``/home``	 | Домашние каталоги пользователей
``/lib``	 | Системные библиотеки
``/mnt``	 | Временные точки монтирования
``/opt``	 | Дополнительное ПО
``/proc``	 | Виртуальная ФС процессов
``/root``	 | Домашний каталог root
``/sbin`` | Системные исполняемые файлы
``/tmp``	 | Временные файлы
``/usr``	 | Пользовательские программы и данные
``/var``	 | Изменяемые данные (логи, очереди)

#### 2. Работа с дисковыми разделами
##### 2.1. Просмотр информации о дисках
```bash
# Список всех блочных устройств
lsblk

# С файловыми системами и UUID
lsblk -f

# Детальная информация о разделах
sudo fdisk -l

# Информация о конкретном диске
sudo fdisk -l /dev/sda

# Использование дискового пространства
df -h

# Размер каталога
du -sh /var/log
```
##### 2.2. Создание разделов
MBR (fdisk) — для дисков до 2 ТБ, максимум 4 первичных раздела:

```bash
sudo fdisk /dev/sdb

# n — создать новый раздел
# p — первичный
# 1 — номер раздела
# Enter — начало по умолчанию
# +10G — размер (или Enter для всего места)
# w — записать изменения
```
GPT (parted) — для больших дисков, до 128 разделов:

```bash
sudo parted -a optimal /dev/sdb
(parted) mklabel gpt
(parted) unit mib
(parted) mkpart primary 1 -1
(parted) print
(parted) quit
```
##### 2.3. Создание файловой системы
```bash
# ext4
sudo mkfs.ext4 /dev/sdb1

# XFS
sudo mkfs.xfs /dev/sdb1

# FAT32
sudo mkfs.fat -F 32 /dev/sdb1
```
##### 2.4. Монтирование
```bash
# Создать точку монтирования
sudo mkdir /disk2

# Смонтировать вручную
sudo mount /dev/sdb1 /disk2

# Проверить
df -h /disk2
```
##### 2.5. Автоматическое монтирование (/etc/fstab)
```bash
# Получить UUID раздела
sudo blkid /dev/sdb1

# Добавить в /etc/fstab
UUID=xxxx-xxxx-xxxx-xxxx /disk2 ext4 defaults 0 0

# Проверить без перезагрузки
sudo mount -a
```
#### 3. Файловые системы в ОС «Альт»
ОС «Альт» (Альт Сервер, Альт Рабочая станция) поддерживает широкий спектр файловых систем .

##### 3.1. Файловые системы для установки Linux
Файловая система	Характеристики
ext2	Нежурналируемая, проста в восстановлении, но долгая проверка после сбоя. Подходит для /boot или read-only разделов 
ext3	Журналируемая, надёжная, средняя производительность 
ext4	Логическое продолжение ext3, журналируемая, позволяет отключить журналирование 
btrfs	Поддерживает снимки (snapshots), сжатие, подтома 
xfs	Высокопроизводительная, рекомендуется для активно используемых ФС при стабильном питании 
jfs	Журналируемая, поддержка перекодирования имён (iocharset) 

##### 3.2. Файловые системы для совместимости
``FAT/FAT32/NTFS`` — поддерживаются в установленной системе, но не для установки на них Linux .

``iso9660`` — для дисков CD/DVD.

##### 3.3. Рекомендации по выбору
Для Альт Рабочая станция по умолчанию используется ext4 под корень, swap создаётся автоматически . Для рабочих станций с BtrFS создаётся раздел с подразделами @ и @home .

#### 4. Пример практического применения
Задача: Добавить новый диск в систему, разметить, отформатировать и смонтировать

> Сценарий: В системе появился новый диск /dev/sdb размером 20 ГБ. Необходимо создать на нём раздел с ext4 и смонтировать в /data.

##### Шаг 1. Проверка текущего состояния
```bash
# Посмотреть все блочные устройства
lsblk

# Вывод покажет /dev/sdb без разделов
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
sda      8:0    0  100G  0 disk
├─sda1   8:1    0   96G  0 part /
└─sda2   8:2    0    4G  0 part [SWAP]
sdb      8:16   0   20G  0 disk
```
##### Шаг 2. Создание раздела
```bash
sudo fdisk /dev/sdb
```
В интерактивном режиме:
- **n** — новый раздел
- **p** — первичный
- **1** — номер 1
- **Enter** — начало по умолчанию
- **Enter** — использовать всё пространство
- **w** — записать

Проверка:

```bash
lsblk
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
sdb      8:16   0   20G  0 disk
└─sdb1   8:17   0   20G  0 part
```
##### Шаг 3. Форматирование
```bash
sudo mkfs.ext4 /dev/sdb1
```
##### Шаг 4. Монтирование
```bash
# Создать точку монтирования
sudo mkdir /data

# Смонтировать
sudo mount /dev/sdb1 /data

# Проверить
df -h /data
Filesystem      Size  Used Avail Use% Mounted on
/dev/sdb1        20G   24K   19G   1% /data
```
##### Шаг 5. Автоматическое монтирование при загрузке
```bash
# Получить UUID
sudo blkid /dev/sdb1
/dev/sdb1: UUID="a1b2c3d4-e5f6-7890-abcd-ef1234567890" TYPE="ext4"

# Добавить в /etc/fstab
echo "UUID=a1b2c3d4-e5f6-7890-abcd-ef1234567890 /data ext4 defaults 0 0" | sudo tee -a /etc/fstab

# Проверить
sudo mount -a
df -h /data
```
##### Шаг 6. Установка прав доступа (при необходимости)
```bash
# Если диск для пользователя
sudo chown -R user:user /data
```
