### Учётные записи пользователей и групп в Alt Linux
В основе организации доступа к ресурсам в Linux, включая ОС «Альт», лежит многопользовательская модель. Каждый пользователь идентифицируется уникальным именем и числовым идентификатором (UID), а его права и привилегии определяются членством в группах .

#### 1. Пользовательские учётные записи
В ОС «Альт» выделяют три типа пользователей, различающихся уровнем полномочий :

| Тип      | UID   | Описание  |
| :---     | :---  | :---      | 
Администратор (root)	    | 0	    | Суперпользователь с неограниченными правами: может читать, изменять и удалять любые файлы, управлять службами и настройками 
Системные пользователи	    | от 1	    | Создаются автоматически для работы внутренних служб и процессов
Обычные пользователи	    | от 500	    | Непривилегированные учётные записи, создаваемые администратором для повседневной работы

Информация о пользователе

Каждая учётная запись хранит следующую информацию :
- Имя пользователя (login name) — уникальное в системе, содержит латинские буквы, цифры, символы _ и .
- UID — числовой идентификатор пользователя
- GID — идентификатор основной группы
- Пароль — в зашифрованном виде
- Полное имя (GECOS) — дополнительная информация (ФИО, контакты)
- Домашний каталог — обычно /home/имя_пользователя
- Начальная оболочка — командный интерпретатор при входе (обычно /bin/bash)

#### 2. База паролей пользователей
В ОС «Альт» для хранения паролей используется схема TCB (Trusted Computing Base), которая отличается от классической схемы с единым файлом /etc/shadow .

Схема TCB
При добавлении новой учётной записи :
- Добавляется строка в файл /etc/passwd
- Создаётся подкаталог /etc/tcb/<имя_пользователя>/
- В этом подкаталоге создаётся файл shadow с хешем пароля

Преимущества TCB:
- Каждый пользователь имеет доступ только к своему файлу пароля
- Снижена вероятность компрометации всех паролей при утечке одного файла
- Позволяет применить мандатное управление доступом к файлам паролей

Хеширование паролей

По умолчанию используется алгоритм yescrypt, обеспечивающий высокую устойчивость к перебору. Ранее применявшийся Blowfish (bcrypt) остаётся доступным .

Проверить текущий алгоритм можно командой:

```bash
passwd -S <имя_пользователя>
# Пример вывода: Password set, yescrypt encryption.
```
Управление схемой хранения паролей

Переключение между схемами осуществляется утилитой control passwd :

```bash
# Схема TCB (по умолчанию)
control passwd tcb

# Классическая схема с единым /etc/shadow
control passwd traditional

# Строгая схема: только root может менять пароли
control passwd restricted
```
#### 3. Учётные записи групп
Группы используются для упрощения управления правами доступа. Пользователь обязательно входит в одну основную группу и может состоять в нескольких дополнительных .

Файл ``/etc/group``

Информация о группах хранится в файле ``/etc/group`` в формате :

```text
имя_группы:пароль:GID:user1,user2,user3...
```
Пример:

```text
developers:x:1001:ivanov,petrov,sidorov
```
Просмотр групп
```bash
# Все группы
cat /etc/group

# Группы конкретного пользователя
groups <имя_пользователя>
id <имя_пользователя>

# Список участников группы
grep <имя_группы> /etc/group
```
Группа ``wheel``

В ОС «Альт» особую роль играет группа ``wheel``. Пользователи, входящие в неё, имеют право получать административные полномочия с помощью su или sudo .

Пользователь, созданный при установке системы, по умолчанию входит в группу wheel .

#### 4. Информация по пользователям в системе
Команды для просмотра информации

| Команда      | Назначение |
| :---         | :---       |
cat /etc/passwd	        | Список всех пользователей
cat /etc/group	        | Список всех групп
id <user>	        | UID, GID и группы пользователя
groups <user>	        | Список групп пользователя
who	        | Активные сеансы
w	        | Активные сеансы с деталями
last	        | История входов
passwd -S <user>	        | Статус пароля пользователя

Формат ``/etc/passwd``

```text
user_name:password:UID:GID:full_name:home_directory:login_shell
```
Пример:

```text
ivanov:x:1001:1001:Иван Иванов:/home/ivanov:/bin/bash
Поле пароля содержит x, так как хеш хранится в TCB-схеме .
```
#### 5. Механизмы получения административных полномочий
В ОС «Альт» существует два основных механизма получения прав суперпользователя .

##### 5.1. Утилита su
Команда su позволяет переключиться на другого пользователя, по умолчанию — на root.

```bash
# Правильный переход (с загрузкой окружения root)
su -

# Неправильный переход (без загрузки окружения)
su
```
> Важно: ключ - (минус) критически важен. Без него :

- Переменная $PATH не будет содержать /sbin и /usr/sbin
- Системные команды могут быть недоступны
- $HOME останется домашним каталогом пользователя

Ограничение доступа к su:

- Управление доступом к su осуществляется утилитой control :

```bash
control su public      # любой пользователь может выполнить su
control su wheel       # только члены wheel могут переключиться в root
control su wheelonly   # только члены wheel могут выполнять su
control su restricted  # только root может выполнять su
```
##### 5.2. Утилита sudo
sudo позволяет выполнять отдельные команды с правами root, не переключаясь полностью на суперпользователя. Это более безопасный и контролируемый способ .

```bash
# Выполнить команду с правами root
sudo apt update

# Получить оболочку root
sudo su -
```
Члены группы wheel по умолчанию имеют право использовать sudo .

##### 5.3. Прямой вход под root
Прямой вход под root в графическую систему запрещён в ОС «Альт» . Это сделано для безопасности: администратор должен осознанно получать привилегии через su или sudo, чтобы действия можно было отследить.

#### 6. Пример практического применения
Задача: Создать группу разработчиков и пользователей с разными правами

Сценарий:
- Создать группу developers
- Создать пользователей ivanov и petrova
- Включить их в группу developers и wheel
- Проверить права и информацию

##### Шаг 1. Создание группы
```bash
sudo groupadd developers
```
##### Шаг 2. Создание пользователей
```bash
# Создать пользователя с домашним каталогом
sudo useradd -m -c "Иван Иванов" ivanov
sudo useradd -m -c "Мария Петрова" petrova

# Установить пароли
sudo passwd ivanov
sudo passwd petrova
```
##### Шаг 3. Добавление в группы
```bash
# Добавить в developers
sudo usermod -aG developers ivanov
sudo usermod -aG developers petrova

# Добавить в wheel (права администратора)
sudo usermod -aG wheel ivanov
sudo usermod -aG wheel petrova
```
> Важно: флаг -a (append) необходим для добавления группы. Без него -G перезапишет список дополнительных групп .

##### Шаг 4. Проверка
```bash
# Проверить информацию о пользователях
id ivanov
id petrova

# Проверить членство в группах
groups ivanov
groups petrova

# Проверить группу developers
grep developers /etc/group
```
Ожидаемый вывод:
```text
uid=1001(ivanov) gid=1001(ivanov) groups=1001(ivanov),10(wheel),1002(developers)
uid=1002(petrova) gid=1002(petrova) groups=1002(petrova),10(wheel),1002(developers)
```
##### Шаг 5. Проверка механизмов получения прав
```bash
# От пользователя ivanov
su -
# Должен запросить пароль root
# Если пароль верный — переход в root

# Или через sudo
sudo whoami
# Вывод: root

##### Шаг 6. Проверка TCB-схемы
bash
# Проверить структуру TCB
ls -la /etc/tcb/
# Должны быть каталоги ivanov, petrova

ls -la /etc/tcb/ivanov/
# Файл shadow

# Проверить алгоритм хеширования
sudo passwd -S ivanov
# Password set, yescrypt encryption.
```
