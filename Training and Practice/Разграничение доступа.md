### Разграничение доступа в Alt Linux
В Alt Linux, как и в любой UNIX-подобной системе, разграничение доступа строится на дискреционной модели (DAC), которая определяет, кто и какие действия может выполнять с файлами и каталогами. Эта модель реализована непосредственно в ядре ОС и дополняется расширенными атрибутами файловой системы .

Базовая модель разграничения доступа
Базовые права доступа назначаются для трёх категорий пользователей и содержат три вида разрешений .

Категории пользователей:
- Владелец (u) — пользователь, создавший файл (или назначенный владельцем).
- Группа (g) — пользователи, входящие в группу-владелец файла.
- Остальные (o) — все прочие пользователи системы.

Права доступа:

| Право	   | Для файла	   | Для каталога  |
| :---     | :---          | :---      | 
r (read)	     | Чтение содержимого	     | Просмотр списка файлов
w (write)	     | Изменение содержимого	     | Создание и удаление файлов
x (execute)	     | Выполнение как программы	     | Вход в каталог (переход в него)

Команда ``chmod`` — основной инструмент управления правами .

```bash
# Числовой режим: 644 = rw-r--r--
chmod 644 file.txt

# Символьный режим
chmod u=rw,go=r file.txt

# Добавить право на выполнение всем
chmod +x script.sh

# Рекурсивно для каталога
chmod -R 755 /var/www
```
Маска ``umask`` определяет права по умолчанию для новых файлов и каталогов. Она вычитается из базовых значений (666 для файлов, 777 для каталогов) .

```bash
# Посмотреть текущую маску
umask

# Установить маску
umask 022  # создаст файлы с правами 644, каталоги 755
```
Изменение атрибутов безопасности файлов

Команда ``chown`` изменяет владельца и группу файла .

```bash
# Сменить владельца
chown user1 file.txt

# Сменить владельца и группу
chown user1:developers file.txt

# Рекурсивно
chown -R user1:developers /project
```
Команда ``chgrp`` меняет только группу-владельца.

Расширенные атрибуты файловой системы ``(ext2/3/4)`` управляются командами ``chattr`` и ``lsattr``.

| Атрибут      | Описание |
| :---         | :---       |
i (immutable)	         | Файл нельзя изменить, удалить или переименовать даже root
a (append-only)	        | Можно только добавлять данные, нельзя изменять существующие
s (secure deletion)        | При удалении блоки заполняются нулями
u (undeletable)	        | Содержимое сохраняется при удалении (можно восстановить)

```bash
# Установить атрибут immutable
sudo chattr +i /etc/passwd

# Проверить атрибуты
lsattr /etc/passwd

# Снять атрибут
sudo chattr -i /etc/passwd
```
Дополнительные атрибуты для исполняемых файлов

Для исполняемых файлов существуют два специальных бита: ``setuid`` и ``setgid``.

``setuid (Set User ID)`` — при запуске файла процесс получает права владельца файла, а не запустившего пользователя. Если владелец — root, программа выполняется с правами root.

```bash
# Установить setuid
chmod u+s /usr/bin/program
chmod 4755 /usr/bin/program
setgid (Set Group ID) — при запуске файла процесс получает права группы-владельца файла.
```
```bash
# Установить setgid
chmod g+s /usr/bin/program
chmod 2755 /usr/bin/program
```
> Важно: setuid и setgid потенциально опасны, так как могут предоставлять повышенные привилегии. Их следует использовать только для проверенных системных утилит .

Поиск файлов с setuid/setgid:

```bash
find / -perm -u+s
find / -perm -g+s
```
Дополнительные атрибуты для каталогов

``sticky bit`` — предотвращает удаление файлов в каталоге пользователями, которые не являются их владельцами. Классический пример — каталог /tmp .

```bash
# Установить sticky bit
chmod +t /shared
chmod 1777 /shared
```
Теперь пользователи могут создавать свои файлы в /shared, но не могут удалять чужие.

``setgid`` на каталоге — все новые файлы и подкаталоги внутри наследуют группу-владельца каталога, а не группу создателя. Это удобно для общих рабочих каталогов .

```bash
# Установить setgid на каталог
chmod g+s /project
chmod 2775 /project
```
Списки контроля доступа (ACL) — расширенный механизм, позволяющий назначать права конкретным пользователям или группам, помимо стандартных трёх категорий .
```bash
# Установить ACL для пользователя
setfacl -m u:ivanov:rwx /project

# Установить ACL для группы
setfacl -m g:developers:rx /project

# Просмотреть ACL
getfacl /project

# Удалить ACL
setfacl -x u:ivanov /project
```
#### Пример практического применения
Задача: Создать общий каталог /srv/dekanat для группы group_dek, чтобы:

- Все файлы в каталоге принадлежали группе group_dek.
- Пользователи могли удалять только свои файлы.
- Обеспечить разный уровень доступа к подкаталогам через ACL.

#### Шаг 1. Создание группы и пользователей
```bash
# Создать группу
sudo groupadd group_dek

# Создать пользователей и добавить в группу
sudo useradd -m -G group_dek dekan
sudo useradd -m -G group_dek sotrudnik
sudo useradd -m -G group_dek, wheel admin_dek
```
#### Шаг 2. Создание каталога и назначение владельца
```bash
# Создать каталог
sudo mkdir -p /srv/dekanat

# Назначить владельца и группу
sudo chown admin_dek:group_dek /srv/dekanat
```
#### Шаг 3. Установка расширенных атрибутов
```bash
# setgid: все новые файлы наследуют группу group_dek
# sticky bit: пользователи удаляют только свои файлы
sudo chmod 3775 /srv/dekanat

# Проверка
ls -ld /srv/dekanat
# Вывод: drwxrwsr-t ... admin_dek group_dek ... /srv/dekanat
#              ^-- setgid    ^-- sticky
```
#### Шаг 4. Создание подкаталогов и настройка ACL
```bash
# Создать подкаталоги
sudo mkdir /srv/dekanat/prikazy /srv/dekanat/informaciya

# Установить владельца (наследуется от родителя)
sudo chown admin_dek:group_dek /srv/dekanat/prikazy /srv/dekanat/informaciya

# Настроить ACL: dekan имеет полный доступ к prikazy
sudo setfacl -m u:dekan:rwx /srv/dekanat/prikazy

# sotrudnik имеет только чтение к prikazy
sudo setfacl -m u:sotrudnik:rx /srv/dekanat/prikazy

# Аналогично для informaciya (наоборот)
sudo setfacl -m u:sotrudnik:rwx /srv/dekanat/informaciya
sudo setfacl -m u:dekan:rx /srv/dekanat/informaciya
```
#### Шаг 5. Проверка
```bash
# Проверить атрибуты каталога
ls -ld /srv/dekanat
getfacl /srv/dekanat/prikazy

# Проверить от имени пользователя dekan
su - dekan
touch /srv/dekanat/prikazy/prikaz.txt      # Успешно
touch /srv/dekanat/informaciya/test.txt    # Отказано (только чтение)
rm /srv/dekanat/prikazy/prikaz.txt         # Успешно (свой файл)

# Проверить от имени sotrudnik
su - sotrudnik
touch /srv/dekanat/informaciya/news.txt    # Успешно
rm /srv/dekanat/prikazy/prikaz.txt         # Отказано (чужой файл, sticky bit)
```
