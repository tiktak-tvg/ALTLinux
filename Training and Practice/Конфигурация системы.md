### Конфигурация системы Alt Linux
В Alt Linux, как и в большинстве современных Linux-дистрибутивов, конфигурация системы организована на нескольких уровнях — от системных настроек до персонального профиля пользователя. Понимание этой иерархии помогает правильно управлять системой и избегать конфликтов настроек.

#### Уровни конфигурации
Конфигурацию Alt Linux можно условно разделить на три уровня:
- **Системный уровень.** Это общесистемные настройки, которые применяются ко всем пользователям. Они хранятся в каталоге ``/etc``. Примером может служить конфигурация системных служб, параметры сети или настройки безопасности. Некоторые настройки можно задавать через графический Центр управления системой или с помощью модулей`` Alterator``.
- **Уровень приложения.** Многие программы имеют собственные конфигурационные файлы, которые могут располагаться как в ``/etc (системные)``, так и в домашнем каталоге пользователя (пользовательские). Например, настройки графической среды KDE или GNOME хранятся в домашнем каталоге, а конфигурация веб-сервера — в /etc.
- **Пользовательский уровень.** Это настройки, относящиеся к конкретному пользователю. Они хранятся в его домашнем каталоге ``(/home/имя_пользователя)`` и позволяют персонализировать рабочее окружение.

#### Пользовательское окружение
Пользовательское окружение (environment) — это совокупность переменных, которые определяют, как работают программы в сеансе пользователя . Ключевые переменные включают:
- **PATH**: список каталогов, в которых система ищет исполняемые файлы.
- **HOME**: путь к домашнему каталогу пользователя.
- **SHELL**: путь к командной оболочке по умолчанию.
- **LANG**: язык системы и локаль.

Переменные окружения можно просмотреть командой env или echo ``$ИМЯ_ПЕРЕМЕННОЙ``. Чтобы переменная была доступна дочерним процессам, её необходимо экспортировать командой ``export``.

#### Пользовательский профиль
Пользовательский профиль — это набор файлов и настроек, которые определяют поведение системы и приложений при входе пользователя. Основные файлы находятся в домашнем каталоге:
- **~/.bash_profile, ~/.bash_login или ~/.profile**: файлы запуска ``(login shell)``. Выполняются один раз при входе в систему. Здесь обычно настраиваются переменные окружения ``(например, PATH)``.
- **~/.bashrc**: файл инициализации ``(interactive shell)``. Выполняется при каждом открытии нового терминала. Здесь задаются псевдонимы ``(alias)``, настройки приглашения командной строки и другие интерактивные параметры .
- **~/.bash_logout**: выполняется при выходе из системы .

Помимо этого, профиль может включать настройки графической среды ``(например, ~/.config для KDE/GNOME)``, настройки браузеров, почтовых клиентов и других приложений.

#### Пример практического применения
Задача: Настроить для пользователя ``test`` удобное окружение командной строки и переменную ``PATH`` для доступа к собственным скриптам.

##### Шаг 1. Вход под пользователем.

```bash
su - test
```
##### Шаг 2. Создание каталога для личных скриптов.

```bash
mkdir -p ~/bin
```
##### Шаг 3. Редактирование ~/.bashrc для настройки интерактивной оболочки.
Добавим в конец файла псевдонимы и настройки:

```bash
nano ~/.bashrc
```
```bash
# Псевдонимы
alias ll='ls -la'
alias ..='cd ..'

# Приглашение командной строки с цветом
PS1='\[\e[32m\]\u@\h\[\e[0m\]:\[\e[34m\]\w\[\e[0m\]\$ '
```
##### Шаг 4. Редактирование ~/.bash_profile для добавления ~/bin в PATH.

```bash
nano ~/.bash_profile
bash
# Добавление личного каталога bin в PATH
export PATH="$HOME/bin:$PATH"
```
##### Шаг 5. Применение изменений.
Изменения в ``~/.bashrc`` вступят в силу при следующем открытии терминала. Для применения ``PATH из ~/.bash_profile`` нужно перелогиниться или выполнить:

```bash
source ~/.bash_profile
```
##### Шаг 6. Проверка.

```bash
# Проверка PATH
echo $PATH | grep "$HOME/bin"

# Проверка псевдонима
ll
```
Теперь пользователь ``test`` может запускать свои скрипты из любого места, просто по имени, и использовать удобные сокращения для команд.
