### Файлы и их атрибуты в Linux
#### 1. Типы файлов
В Linux, в соответствии с философией «всё есть файл», существует несколько типов файлов. Тип файла определяется первым символом в выводе команды ls -l.

##### 1.1. Основные типы файлов
Символ	Тип	Описание
| Символ   | Тип   | Описание  |
| :---     | :---  | :---      | 
-	     | Обычный файл	     | Текстовые, бинарные, изображения, архивы
d	     | Каталог	     | Содержит другие файлы и каталоги
l	     | Символическая ссылка	     | Указывает на другой файл по пути
c	     | Символьное устройство	     | Устройства посимвольного ввода-вывода (терминалы, мышь)
b	     | Блочное устройство	     | Устройства блочного ввода-вывода (диски, разделы)
s	     | Сокет	     | Межпроцессное взаимодействие через сеть
p      | 	Именованный канал (FIFO)	     | Межпроцессное взаимодействие через pipe

##### 1.2. Примеры определения типов
bash
# Просмотр типов файлов
ls -l /dev/sda        # brw-rw----  блочное устройство
ls -l /dev/tty        # crw-rw-rw-  символьное устройство
ls -l /etc/passwd     # -rw-r--r--  обычный файл
ls -l /etc            # drwxr-xr-x  каталог
ls -l /usr/bin/python3  # lrwxrwxrwx  символическая ссылка
Пример вывода:

text
brw-rw----  1 root disk    8,   0 сен 23 10:00 /dev/sda
crw-rw-rw-  1 root tty     5,   0 сен 23 10:00 /dev/tty
-rw-r--r--  1 root root  2847 сен 15 08:30 /etc/passwd
drwxr-xr-x 20 root root  4096 сен 20 09:15 /etc
lrwxrwxrwx  1 root root     9 сен 15 08:30 /usr/bin/python3 -> python3.11

##### 1.3. Определение типа через команду file
bash
file /etc/passwd
# /etc/passwd: ASCII text

file /bin/bash
# /bin/bash: ELF 64-bit LSB executable, x86-64

file /dev/sda
# /dev/sda: block special (8/0)

file /usr/bin/python3
# /usr/bin/python3: symbolic link to python3.11

##### 1.4. Символические и жёсткие ссылки
Жёсткая ссылка (hard link) — это дополнительное имя для того же inode. Файл существует, пока есть хотя бы одна жёсткая ссылка.

Символическая ссылка (symlink) — это отдельный файл, содержащий путь к другому файлу.

bash
# Создать жёсткую ссылку
ln file.txt hardlink.txt

# Создать символическую ссылку
ln -s file.txt symlink.txt

# Просмотр ссылок
ls -li file.txt hardlink.txt symlink.txt
Различия:

Характеристика	Жёсткая ссылка	Символическая ссылка
Inode	Тот же	Другой
Работа после удаления оригинала	Да	Нет (битая ссылка)
Ссылка на каталог	Нет	Да
Ссылка на другой раздел	Нет	Да
Размер	Равен оригиналу	Равен длине пути

#### 2. Утилиты для работы с файлами
##### 2.1. Просмотр и навигация
bash
ls -la              # список с атрибутами
ls -lh              # человекочитаемые размеры
ls -li              # с inode
ls -ltr             # сортировка по времени
tree                # дерево каталогов
stat file.txt       # подробная информация
file file.txt       # тип файла

##### 2.2. Создание и удаление
bash
touch file.txt              # создать пустой файл
mkdir dir                   # создать каталог
mkdir -p a/b/c              # создать вложенные каталоги
rm file.txt                 # удалить файл
rm -r dir                   # удалить каталог рекурсивно
rmdir dir                   # удалить пустой каталог

2.3. Копирование и перемещение
bash
cp file1 file2              # копировать файл
cp -r dir1 dir2             # копировать каталог
cp -a dir1 dir2             # с сохранением атрибутов
mv file1 file2              # переместить/переименовать
mv file dir/                # переместить в каталог

##### 2.4. Просмотр содержимого
bash
cat file.txt                # вывести содержимое
less file.txt               # постраничный просмотр
head -n 10 file.txt         # первые 10 строк
tail -n 10 file.txt         # последние 10 строк
tail -f /var/log/syslog     # слежение в реальном времени

2.5. Поиск файлов
bash
find /path -name "*.txt"           # по имени
find /path -type f -size +10M      # файлы больше 10 МБ
find /path -mtime -7               # изменённые за 7 дней
find /path -user user1             # принадлежащие user1
find /path -perm 644               # с правами 644

locate file.txt                    # быстрый поиск по базе
which ls                           # путь к команде
whereis ls                         # путь + man-страницы

##### 2.6. Права доступа
bash
chmod 755 file              # символический/числовой
chmod u+x file              # добавить execute владельцу
chown user:group file       # сменить владельца
chgrp group file            # сменить группу
umask                       # маска прав по умолчанию

##### 2.7. Расширенные атрибуты
bash
lsattr file                 # просмотр атрибутов
chattr +i file              # сделать неизменяемым
chattr -i file              # снять неизменяемость
chattr +a file              # только добавление
getfacl file                # просмотр ACL
setfacl -m u:user:rw file   # установка ACL

##### 2.8. Специальные атрибуты
Атрибут	Описание
i	Неизменяемый (immutable)
a	Только добавление (append-only)
c	Автоматическое сжатие
d	Не включать в dump
s	Безопасное удаление
u	Сохранять при удалении
Пример:

bash
# Защитить конфигурационный файл от изменений
sudo chattr +i /etc/passwd
# Теперь даже root не может удалить или изменить файл

# Снять защиту
sudo chattr -i /etc/passwd

#### 3. Индексные дескрипторы (inode)
Inode (index node) — это структура данных в файловой системе, содержащая всю информацию о файле, кроме его имени и содержимого.

##### 3.1. Что хранит inode
Поле	Описание
Номер inode	Уникальный идентификатор
Тип файла	Обычный, каталог, устройство
Права доступа	rwx для владельца, группы, остальных
Владелец (UID)	Пользователь-владелец
Группа (GID)	Группа-владелец
Размер	В байтах
Временные метки	atime, mtime, ctime
Счётчик ссылок	Количество жёстких ссылок
Указатели на блоки	Где хранятся данные
Расширенные атрибуты	ACL, метки безопасности
Важно: inode не хранит имя файла — имя хранится в каталоге, который сопоставляет имя и номер inode.

##### 3.2. Просмотр inode
bash
# Просмотр inode файла
ls -li file.txt
# 1234567 -rw-r--r-- 1 user user 1024 сен 23 10:00 file.txt

# Подробная информация
stat file.txt
Пример вывода stat:

text
  File: file.txt
  Size: 1024            Blocks: 8          IO Block: 4096   regular file
Device: 801h/2049d      Inode: 1234567     Links: 1
Access: (0644/-rw-r--r--)  Uid: ( 1000/    user)   Gid: ( 1000/    user)
Access: 2026-09-23 10:00:00.000000000 +0300
Modify: 2026-09-23 10:00:00.000000000 +0300
Change: 2026-09-23 10:00:00.000000000 +0300
 Birth: 2026-09-23 09:00:00.000000000 +0300
Расшифровка времён:

Метка	Описание
Access (atime)	Время последнего чтения
Modify (mtime)	Время последнего изменения содержимого
Change (ctime)	Время последнего изменения inode (права, владелец)
Birth	Время создания (если поддерживается)

##### 3.3. Номер inode и файловая система
bash
# Найти файлы с одинаковым inode (жёсткие ссылки)
find / -inum 1234567 2>/dev/null

# Показать inode для всех файлов в каталоге
ls -li /etc/ | head

# Inode каталога
ls -di /etc
# 131073 /etc

##### 3.4. Исчерпание inode
Inode выделяются при создании файловой системы. Если все inode закончились, новые файлы создать нельзя, даже если есть свободное место.

bash
# Проверка использования inode
df -i
Пример вывода:

text
Filesystem      Inodes  IUsed   IFree IUse% Mounted on
/dev/sda1      6553600 250000 6303600    4% /
Если IUse% = 100% — новые файлы создать невозможно. Решение: удалить множество мелких файлов или пересоздать ФС с большим числом inode.

#### 4. Пример практического применения
Задача: Найти и удалить старые файлы, защитить критичный конфигурационный файл
Сценарий:

В /var/log/myapp/ накопились логи. Нужно удалить файлы старше 30 дней.

Конфигурационный файл /etc/myapp/config.conf нужно защитить от случайного изменения.

Проверить, сколько места и inode занимают логи.

##### Шаг 1. Анализ ситуации
bash
# Проверка места
df -h /var/log/myapp/
Вывод:

text
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        50G   45G  2.5G  95% /var
bash
# Проверка inode
df -i /var/log/myapp/
Вывод:

text
Filesystem      Inodes  IUsed   IFree IUse% Mounted on
/dev/sda1      3276800 250000 3026800    8% /
bash
# Просмотр логов
ls -lh /var/log/myapp/
Вывод:

text
-rw-r--r-- 1 root root 1.2G сен 23 10:00 app.log
-rw-r--r-- 1 root root 800M авг 15 09:00 app.log.1
-rw-r--r-- 1 root root 500M июл 10 08:00 app.log.2
-rw-r--r-- 1 root root 300M июн 05 07:00 app.log.3

##### Шаг 2. Поиск старых файлов
bash
# Найти файлы старше 30 дней
find /var/log/myapp/ -name "*.log*" -mtime +30 -type f
Вывод:

text
/var/log/myapp/app.log.2
/var/log/myapp/app.log.3
bash
# С подробной информацией
find /var/log/myapp/ -name "*.log*" -mtime +30 -type f -exec ls -lh {} \;
Вывод:

text
-rw-r--r-- 1 root root 500M июл 10 08:00 /var/log/myapp/app.log.2
-rw-r--r-- 1 root root 300M июн 05 07:00 /var/log/myapp/app.log.3

##### Шаг 3. Просмотр inode и жёстких ссылок
bash
# Просмотр inode файлов
ls -li /var/log/myapp/
Вывод:

text
1234567 -rw-r--r-- 1 root root 1.2G сен 23 10:00 app.log
1234568 -rw-r--r-- 1 root root 800M авг 15 09:00 app.log.1
1234569 -rw-r--r-- 2 root root 500M июл 10 08:00 app.log.2
1234570 -rw-r--r-- 1 root root 300M июн 05 07:00 app.log.3
Обратите внимание: у app.log.2 счётчик ссылок = 2. Это значит, есть ещё одна жёсткая ссылка на этот файл.

bash
# Найти все ссылки на inode 1234569
find / -inum 1234569 2>/dev/null
Вывод:

text
/var/log/myapp/app.log.2
/backup/app.log.2
Файл /backup/app.log.2 — это резервная копия. Удаление оригинала не удалит данные, пока есть ссылка.

##### Шаг 4. Удаление старых файлов
bash
# Удалить файлы старше 30 дней
find /var/log/myapp/ -name "*.log*" -mtime +30 -type f -delete

# Проверка
ls -lh /var/log/myapp/
Вывод:

text
-rw-r--r-- 1 root root 1.2G сен 23 10:00 app.log
-rw-r--r-- 1 root root 800M авг 15 09:00 app.log.1
Важно: файл app.log.2 не удалён полностью, так как на него есть жёсткая ссылка в /backup/. Данные остаются на диске, пока существует хотя бы одна ссылка.

##### Шаг 5. Проверка освобождённого места
bash
df -h /var/log/myapp/
Вывод:

text
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        50G  43G  4.5G  91% /

##### Шаг 6. Защита конфигурационного файла
bash
# Просмотр текущих атрибутов
lsattr /etc/myapp/config.conf
Вывод:

text
----------------e----- /etc/myapp/config.conf
bash
# Установить атрибут immutable (неизменяемый)
sudo chattr +i /etc/myapp/config.conf

# Проверка
lsattr /etc/myapp/config.conf
Вывод:

text
----i-----------e----- /etc/myapp/config.conf
Проверка защиты:

bash
# Попытка изменить файл
echo "test" >> /etc/myapp/config.conf
Вывод:

text
bash: /etc/myapp/config.conf: Operation not permitted
Даже root не может изменить файл, пока установлен атрибут i.

bash
# Снять защиту (при необходимости)
sudo chattr -i /etc/myapp/config.conf

##### Шаг 7. Создание символической ссылки для удобства
bash
# Создать ссылку на актуальный лог
ln -s /var/log/myapp/app.log /var/log/myapp/current.log

# Проверка
ls -li /var/log/myapp/
Вывод:

text
1234567 -rw-r--r-- 1 root root 1.2G сен 23 10:00 app.log
1234568 -rw-r--r-- 1 root root 800M авг 15 09:00 app.log.1
1234600 lrwxrwxrwx 1 root root   25 сен 23 10:30 current.log -> /var/log/myapp/app.log
Обратите внимание: символическая ссылка имеет свой inode (1234600) и маленький размер (25 байт — длина пути).

##### Шаг 8. Итоговая проверка
bash
# Место
df -h /var/log/myapp/

# Inode
df -i /var/log/myapp/

# Файлы
ls -li /var/log/myapp/

# Атрибуты
lsattr /etc/myapp/config.conf

# Проверка ссылок
readlink /var/log/myapp/current.log

Разбор использованных инструментов:
Инструмент	Назначение
df -h	Проверка места
df -i	Проверка inode
ls -li	Просмотр inode и ссылок
ls -lh	Человекочитаемые размеры
find -mtime	Поиск по времени изменения
find -inum	Поиск по inode
find -delete	Удаление найденных файлов
stat	Подробная информация о файле
chattr +i	Установка неизменяемости
lsattr	Просмотр атрибутов
ln -s	Создание символической ссылки
readlink	Просмотр цели ссылки
