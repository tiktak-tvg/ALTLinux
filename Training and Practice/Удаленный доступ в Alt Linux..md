### Удаленный доступ в Alt Linux.
В Alt Linux удаленный доступ и сетевые настройки реализованы через комбинацию системных утилит и подсистем. Ниже приведен обзор ключевых аспектов с примерами.

#### Сетевые настройки (Etcnet)
В Alt Linux для настройки сети используется подсистема Etcnet, которая хранит конфигурацию в каталоге ``/etc/net``. Это декларативный подход, позволяющий гибко управлять интерфейсами, включая мосты, VLAN и агрегацию .

Основные файлы для интерфейса (``/etc/net/ifaces/<интерфейс>/``):
- ``options`` — основные параметры (тип соединения, способ получения IP).
- ``ipv4address`` — IP-адрес и маска (для статики).
- ``ipv4route`` — шлюз по умолчанию.
- ``resolv.conf`` — DNS-серверы .

Пример практического применения:
- Настроим статический IP для интерфейса ``enp0s3`` с адресом ``192.168.1.100/24`` и шлюзом ``192.168.1.1``.
- Отредактируйте файл ``/etc/net/ifaces/enp0s3/options``: убедитесь, что ``BOOTPROTO=static и ONBOOT=yes``.
- Задайте IP-адрес: ``echo "192.168.1.100/24" > /etc/net/ifaces/enp0s3/ipv4address``.
- Задайте шлюз: ``echo "default via 192.168.1.1" > /etc/net/ifaces/enp0s3/ipv4route``.
- Укажите DNS: ``echo "nameserver 8.8.8.8" > /etc/net/ifaces/enp0s3/resolv.conf``.
- Примените настройки: ``systemctl restart network (или перезагрузите систему)``.

#### Разрешение имен (DNS)
Разрешение имен в Alt Linux — это модульная система на базе glibc, использующая /etc/nsswitch.conf для определения порядка источников (файлы, DNS, mDNS и т.д.) .

Как это работает:
- Стандартный файл ``/etc/resolv.conf`` содержит адреса DNS-серверов.
- В Alt Linux управление этим файлом может осуществляться через Etcnet (для статики копируется из ifaces, для DHCP — через хуки) или через openresolv (если установлен), что позволяет избежать конфликтов при смене сетей .

Пример практического применения:
- Проверка разрешения имен и диагностика проблем.
- Проверьте текущие настройки: ``cat /etc/resolv.conf`` (должны быть nameserver и search) .
- Проверьте порядок источников: ``grep hosts /etc/nsswitch.conf`` (обычно files dns) .
- Проверьте разрешение имени: ``host ya.ru или nslookup ya.ru``.

#### Утилиты сетевой диагностики
В Alt Linux доступен стандартный набор инструментов для диагностики, а также специализированные утилиты.
- Стандартные: ``ping, traceroute, ss, ip``.
- Специализированные: ``mtr`` (объединяет ping и traceroute) , ``netwatch`` (диагностика в реальном времени) .
- Средства Alt: ``alteratorctl diag`` — запуск диагностических тестов (например, проверка ``resolv.conf`` или служб домена) .

Диагностика доступности и маршрутов:
- ``ping``: Базовая проверка ICMP.
- ``traceroute``: Показывает путь пакетов до узла.
- ``mtr``: Комбинирует ping и traceroute, работает в реальном времени и показывает статистику потерь на каждом хопе. Это лучший инструмент для поиска проблем с маршрутизацией.
- ``ss``: Современная замена netstat. Показывает сокеты (``-tulnp``для слушающих портов с процессами) и установленные соединения ``(-tn state established)``.

Анализ трафика и портов:
- ``tcpdump``: Захват пакетов из командной строки. Незаменим для глубокого анализа (tcpdump -i any port 53).
- ``nmap``: Сканер сети. Позволяет обнаружить хосты и открытые порты (nmap -sT -p 1-1024 localhost).

Мониторинг нагрузки:
- ``iftop``: Показывает трафик в реальном времени, сгруппированный по хостам.
- ``nethogs``: Показывает трафик, сгруппированный по процессам.

Пример практического применения (диагностика недоступности сайта):
Используем комбинацию инструментов, следуя принципу «от простого к сложному».
- ``ping -c 4 8.8.8.8`` — проверка наличия интернета.
- ``host ya.ru`` — проверка DNS.
- ``mtr -rwc 20 ya.ru`` — поиск проблемных узлов на пути.
- ``nc -zv ya.ru 443`` — проверка доступности порта 443 (HTTPS).
- ``sudo tcpdump -i any host ya.ru -c 20`` — если порт «не отвечает», захватываем трафик, чтобы увидеть, уходят ли пакеты и приходят ли ответы (например, RST).

#### SSH – Secure Shell
В Alt Linux для удаленного доступа используется OpenSSH. Конфигурационный файл сервера находится по пути /etc/openssh/sshd_config .

Основные возможности:
- Аутентификация по паролю (PasswordAuthentication yes) .
- Аутентификация по ключу (PubkeyAuthentication yes) — более безопасный метод .
- Ограничение доступа через групповые политики (например, только для администраторов) .
- Запрет входа root (PermitRootLogin no) — по умолчанию прямой вход root запрещен из соображений безопасности .

Пример практического применения:
- Настройка доступа по ключу для пользователя user.
- На клиенте сгенерируйте ключи: ``ssh-keygen -t ed25519``.
- Скопируйте публичный ключ на сервер: ``ssh-copy-id user@server``.
- Проверьте вход: ssh user@server (пароль запрашиваться не должен).
- Для усиления безопасности отключите вход по паролю в ``/etc/openssh/sshd_config``, установив ``PasswordAuthentication no``, и перезапустите службу: ``systemctl restart sshd``
