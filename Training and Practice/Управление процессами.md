### Управление процессами в Alt Linux
#### Атрибуты процессов
Каждый процесс в Linux характеризуется набором атрибутов, хранящихся в структуре ядра и доступных через виртуальную файловую систему /proc.

#### Основные атрибуты

| Атрибут	     | Описание   |
| :---         | :---       |
PID	         | Уникальный идентификатор процесса
PPID	        | Идентификатор родительского процесса
UID/GID	        | Реальный, эффективный и сохранённый идентификаторы пользователя и группы
State (Состояние)	        | Текущее состояние процесса (R, S, D, Z, T)
PRI	        | Приоритет процесса (чем меньше, тем выше приоритет)
NI (Nice)	        | Nice-значение для корректировки приоритета
VmSize/VmRSS	        | Размер виртуальной и резидентной памяти
Threads	        | Количество потоков
SigPnd/SigBlk	        | Ожидающие и заблокированные сигналы

#### Просмотр атрибутов:

```bash
# Подробная информация о процессе
cat /proc/<PID>/status

# Состояние процесса из /proc/<PID>/stat
cat /proc/<PID>/stat
```
В файле /proc/<PID>/status поле State содержит один из символов, описывающих состояние процесса .

#### Инструменты анализа процессов в системе

##### ps — снимок процессов

```bash
# Все процессы с деталями
ps aux

# Полный список
ps -ef

# Дерево процессов
ps -ef --forest

# Топ-10 по памяти
ps -eo pid,ppid,user,cmd,%mem,%cpu --sort=-%mem | head

# По пользователю
ps -u postgres
```
##### top / htop — мониторинг в реальном времени

```bash
# Запуск top
top

# Пакетный режим
top -b -n 1 | head -20

# htop (требует установки)
sudo apt install htop
htop

Горячие клавиши top: P — сортировка по CPU, M — по памяти, k — kill, r — renice, 1 — показать ядра .

pstree — дерево процессов
bash
pstree
pstree -p          # с PID
pstree -a          # с аргументами
```
##### Другие инструменты

| Инструмент	     | Назначение   |
| :---         | :---       |
``pgrep``	         | Поиск PID по имени
``pidof``	         | PID по имени программы
``strace``	        | Трассировка системных вызовов
``lsof``	         | Открытые файлы процесса
``vmstat``	        | Статистика виртуальной памяти

#### Состояния процессов
Состояние процесса отображается в поле State файла /proc/<PID>/status или в столбце STAT команды ps .

| Код      | Состояние  | Описание  |
| :---     | :---       | :---      | 
``R``	     | Running	     | Выполняется или готов к выполнению
``S``	     | Sleeping	     | Спит, ожидая прерывания (ожидание события)
``D``	     | Uninterruptible sleep	     | Непрерываемый сон (обычно ожидание I/O)
``Z``	     | Zombie	     | Зомби (завершён, но родитель не прочитал код возврата)
``T``	     | Stopped	     | Остановлен сигналом или трассировкой
``t``	     | Tracing stop	     | Остановлен трассировщиком (с Linux 2.6.33)
``I``	     | Idle	     | Простаивает (с Linux 4.14)
``X``	     | Dead	     | Мёртв

Пример вывода ps с состояниями:

```text
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root         1  0.0  0.1 168556 13140 ?        Ss   10:15   0:03 /sbin/init
postgres  1234  0.5  2.3 350120 95000 ?        Ss   10:20   0:15 postgres: checkpointer
user      5678  2.0  1.5 500000 60000 pts/0    R+   14:30   0:05 ./script.sh
```
Расшифровка STAT:
- **Ss** — спящий (S), лидер сессии (s)
- **R+** — выполняется (R), в foreground (+)
- **D** — непрерываемый сон (проблема с диском)

**Зомби-процессы**: если в выводе ps много процессов со статусом Z, это указывает на проблему в родительском процессе, который не собирает коды завершения потомков.

##### Работа с заданиями (jobs)
``Job control`` — это механизм управления заданиями в интерактивной оболочке bash, позволяющий приостанавливать, возобновлять и переключать процессы между передним и задним планом .

#### Основные команды

| Команда      | Действие   |
| :---         | :---       |
``jobs``	         | Список активных заданий
``jobs -l``	         | С PID
``jobs -r``	         | Только выполняющиеся
``jobs -s``	         | Только остановленные
``bg %N``	         | Возобновить задание N в фоне
``fg %N``	         | Возобновить задание N на переднем плане
``Ctrl+Z``	         | Приостановить текущее задание
``Ctrl+C``	         | Прервать текущее задание

Пример работы
```bash
# Запуск длительной команды в фоне
sleep 300 &
[1] 12345

# Список заданий
jobs
[1]+  Running                 sleep 300 &

# Приостановить (Ctrl+Z)
^Z
[1]+  Stopped                 sleep 300

# Возобновить в фоне
bg
[1]+ sleep 300 &

# Вернуть на передний план
fg
sleep 300
```
Пример вывода jobs
```text
[1]-  Running                 ./longscript.sh &
[2]+  Stopped                 vim file.txt
[1], [2] — номера заданий

- — предыдущее задание

+ — текущее задание
```
#### Приоритеты выполнения процессов
Приоритет определяет, в каком порядке процессы получают доступ к CPU. В Linux управление приоритетом осуществляется через nice-значение .

##### Nice-значение


| Nice     | Приоритет         | Описание                   |
| :---     | :---              | :---                       | 
-20	       | Наивысший	       | Процесс получает больше CPU
0	         | По умолчанию	     | Базовый уровень
19	       | Наименьший	       | Процесс получает меньше CPU

Формула: PRI (new) = PRI (old) + NI, где PRI (old) фиксирован на 80 .

Ограничения:
- Только root может устанавливать отрицательные nice-значения (повышать приоритет).
- Обычные пользователи могут только понижать приоритет (увеличивать nice).

##### Команда nice — запуск с приоритетом
```bash
# Запуск с низким приоритетом (nice = 10)
nice -n 10 ./script.sh

# Запуск с высоким приоритетом (только root)
sudo nice -n -10 ./critical_task.sh
```
##### Команда renice — изменение приоритета
```bash
# Понизить приоритет процесса
renice 10 -p 1234

# Повысить приоритет (только root)
sudo renice -10 -p 1234

# Для всех процессов пользователя
sudo renice 5 -u user1
```
Пример вывода renice:

```text
1234 (process ID) old priority 0, new priority 10
```
Изменение приоритета через top
```bash
top
# Нажать r
# Ввести PID
# Ввести новое nice-значение
```
##### Графический интерфейс Alt Linux

В Системном мониторе Alt Linux на вкладке Процессы можно изменить приоритет процесса через контекстное меню: Изменить приоритет процесса → выбрать уровень nice .

#### Пример практического применения
Задача: Сделать резервное копирование, не мешающее работе пользователей.

Сценарий: Нужно скопировать большой каталог /data в /backup, но так, чтобы процесс не забирал все ресурсы CPU.

##### Шаг 1. Запуск с пониженным приоритетом
```bash
# nice -n 19 — самый низкий приоритет
nice -n 19 rsync -av /data/ /backup/ &
```
##### Шаг 2. Просмотр задания и приоритета
```bash
# Список заданий
jobs -l
[1]+ 12345 Running    nice -n 19 rsync -av /data/ /backup/ &

# Просмотр приоритета процесса
ps -o pid,ni,pri,cmd -p 12345
  PID  NI PRI CMD
12345  19  99 rsync -av /data/ /backup/
```
##### Шаг 3. Изменение приоритета на лету
```bash
# Повысить приоритет (если нужно ускорить)
sudo renice -5 -p 12345
12345 (process ID) old priority 19, new priority -5

# Проверить
ps -o pid,ni,pri,cmd -p 12345
  PID  NI PRI CMD
12345  -5  75 rsync -av /data/ /backup/
```
##### Шаг 4. Приостановка и возобновление
```bash
# Приостановить (Ctrl+Z в терминале или kill -STOP)
kill -STOP 12345

# Возобновить в фоне
kill -CONT 12345
# или
bg %1
```
##### Шаг 5. Завершение при необходимости
```bash
# Мягкое завершение
kill 12345

# Принудительное (если не реагирует)
kill -9 12345
```
##### Шаг 6. Проверка состояния
```bash
# Просмотр состояния процесса
cat /proc/12345/status | grep State
State:  S (sleeping)

# Или через ps
ps -o pid,stat,ni,cmd -p 12345
  PID STAT  NI CMD
12345 S     19 rsync -av /data/ /backup/
```
